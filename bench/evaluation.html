Verification cost of a signed Digital Product Passport

How expensive is it to prove a garment's chain of custody hasn't been forged? We measure verification latency against chain length, and the size a passport adds to a tag.

Method

Each passport is a hash chain of signed supply-chain events (Ed25519 over SHA-256(seq ‖ payloadHash ‖ prevHash); see server/data/provenance.js). Verification re-derives every hash and checks every signature. We build synthetic chains of n ∈ {1…512} events by tiling the real PANGAIA passport's chapters (so event payloads are of realistic length), warm up, then time verifyEvents() over many repetitions and report the mean and 95th percentile. Reproduce with npm run bench, which writes bench/results.json — this page charts it.

Findings

  • Verification is linear, O(n) in the number of events — one SHA-256 + one Ed25519 check per event. The per-event cost is flat (the green line), confirming no super-linear blow-up.
  • It's effectively free at real sizes. A real garment passport has a handful of events; even a 64-event chain verifies in single-digit milliseconds — imperceptible in the scan-to-verdict flow.
  • Tag footprint is small and linear — roughly per event. The tag itself only needs the head hash (32 bytes); the full chain is fetched from the API, so the physical QR/NFC payload is constant regardless of chain length.
  • Security cost is asymmetric in our favour: forging one event means re-signing it and every downstream event, none of whose private keys the attacker holds — while a verifier pays only the linear cost above.
