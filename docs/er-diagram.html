Design notes

  • The provenance ledger is a first-class table. provenance_event stores every signed supply-chain event with its prev_hash, record_hash and signature. Verification reads signed rows straight from the database and re-derives the chain — it doesn't trust an in-memory rebuild.
  • Keys are separated from signatures. authority holds only public keys; private keys live in a keystore outside the database (an HSM in production). A verifier needs the DB and the public keys, never the private keys.
  • Normalised where it must join, document where it must not. Materials and evidence are queryable rows; a passport's care/LCA/story blocks live in passport.doc. This keeps the schema honest without flattening deeply-nested editorial content into dozens of thin tables.
  • Referential integrity is enforced — PRAGMA foreign_keys = ON, with ON DELETE CASCADE from passport → material → evidence and passport → provenance_event.
SQLite for a self-contained, zero-config thesis artifact. The schema is standard SQL; the same DDL and access layer port to Postgres by swapping the driver — noted as future work.
